# V2 Implementation: History & Learning System

## Overview

Version 0.4.0 introduces a SQLite-based history tracking system with learning capabilities. This document explains the feature implementation, database schema, and user flows.

---

## Features Added

### 1. Command History Tracking

Every command generated by Shell Agent (whether from AI or shortcuts) is now tracked in a local SQLite database.

**What's Tracked:**
- User's natural language query
- Generated shell command
- Source (AI or shortcut)
- Working directory
- Execution status (executed or not)
- Exit code (if executed)
- Timestamp

### 2. Usage Statistics

Aggregated statistics about command usage, including:
- Total commands generated
- Execution rate
- AI vs Shortcut breakdown
- Most frequently used commands

### 3. Smart Shortcut Suggestions (Command-Based)

The system learns from your usage patterns and suggests creating shortcuts for frequently used commands. **Key advantage:** Handles typos, synonyms, and different phrasings automatically.

**How It Works:**
1. Every command is tracked in `query_stats` table (keyed by COMMAND)
2. Different queries generating the same command are counted together
3. When a command is used 3+ times, it becomes a suggestion candidate
4. User runs `s --suggest-shortcuts` to see and create shortcuts interactively
5. AI generates shortcut name, user can accept or edit

## New Commands

| Command | Description |
|---------|-------------|
| `s --history` | View recent command history |
| `s --history --limit N` | Limit results to N entries |
| `s --history --search "term"` | Search history by query or command |
| `s --stats` | View usage statistics |
| `s --clear-history --all` | Clear all history (with confirmation) |
| `s --clear-history --older-than N` | Clear entries older than N days |
| `s --suggest-shortcuts` | Get personalized shortcut suggestions |
| `s --suggest-shortcuts --threshold N` | Set minimum use count for suggestions |

## Database Schema

### Location

```
~/.shell-agent/history.db
```

File permissions: `0o600` (owner read/write only)

### Tables

#### `history` (Auto-cleaned)

Stores recent command history. Automatically cleaned based on retention settings.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER | Primary key |
| query | TEXT | User's natural language input |
| command | TEXT | Generated shell command |
| source | TEXT | "ai" or "shortcut" |
| working_directory | TEXT | CWD when command was generated |
| executed | INTEGER | 0=not run, 1=user executed it |
| exit_code | INTEGER | Command exit code (NULL if not executed) |
| created_at | TEXT | ISO timestamp |

**Retention Policy:**
- Default: Delete entries older than 30 days
- Cap at 2000 entries maximum
- Cleanup runs automatically once per day

#### `query_stats` (Never deleted)

Aggregated usage statistics **keyed by COMMAND** to handle query variations (typos, synonyms, different phrasings). Only grows by unique commands, stays tiny forever.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER | Primary key |
| command | TEXT | Unique shell command (UNIQUE KEY) |
| source | TEXT | "ai" or "shortcut" |
| use_count | INTEGER | Total times this command was used |
| success_count | INTEGER | Times it succeeded (exit_code=0) |
| suggested | INTEGER | 0=not suggested, 1=already suggested |
| first_used | TEXT | First time command was used |
| last_used | TEXT | Most recent use |

**Key Design:** Commands are the unique key, not queries. This means:
- User types "find large files" → command: `find . -size +100M` → Entry A
- User types "find larg files" (typo) → same command → Entry A (count++)
- User types "show large files" (synonym) → may generate same command → Entry A (count++)

**Size Estimate:** Even a power user will have 200-500 unique commands. Table stays under 100KB forever.

#### `metadata`

Key-value store for database settings.

| Column | Type | Description |
|--------|------|-------------|
| key | TEXT | Setting name |
| value | TEXT | Setting value |

## User Flows

### Flow 1: Using a Command

```
User runs: s find large files
                │
                ▼
┌─────────────────────────────────────┐
│ 1. Check shortcuts.json             │
│    "find" not found → continue      │
└─────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│ 2. Call AI provider                 │
│    Generate: find . -size +100M     │
└─────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│ 3. Record in database               │
│                                     │
│    history table:                   │
│    INSERT new row (executed=0)      │
│                                     │
│    query_stats table:               │
│    INSERT or UPDATE (use_count++)   │
└─────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│ 4. Show command, ask confirmation   │
│    > find . -size +100M             │
│    > Execute? (y/n/e/c/edit)        │
└─────────────────────────────────────┘
                │
                ▼ (User executes)
┌─────────────────────────────────────┐
│ 5. Update database                  │
│                                     │
│    history table:                   │
│    SET executed=1, exit_code=0      │
│                                     │
│    query_stats table:               │
│    INCREMENT success_count          │
└─────────────────────────────────────┘
```

### Flow 2: Viewing History

```
User runs: s --history
                │
                ▼
┌─────────────────────────────────────┐
│ Query: SELECT * FROM history        │
│        ORDER BY created_at DESC     │
│        LIMIT 20                     │
└─────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│ Display:                            │
│                                     │
│ ✓ [2h ago] success (ai)             │
│ $ find . -size +100M                │
│ Query: find large files             │
│                                     │
│ ○ [1d ago] not executed (shortcut)  │
│ $ kill -9 $(lsof -t -i:3000)        │
└─────────────────────────────────────┘
```

### Flow 3: Getting Shortcut Suggestions

```
User runs: s --suggest-shortcuts
                │
                ▼
┌─────────────────────────────────────┐
│ Query: SELECT * FROM query_stats    │
│        WHERE source = 'ai'          │
│          AND use_count >= 3         │
│          AND suggested = 0          │
│        ORDER BY use_count DESC      │
│                                     │
│ Results keyed by COMMAND            │
│ (handles typos & synonyms)          │
└─────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│ Display suggestion:                 │
│                                     │
│ Command: lsof -ti:3000 | xargs kill │
│ Used: 5 times                       │
│                                     │
│ Create shortcut? (y/N): _           │
└─────────────────────────────────────┘
                │
                ▼ (User confirms)
┌─────────────────────────────────────┐
│ Flow:                               │
│ 1. Show auto-generated name: killport│
│ 2. Ask user to confirm or edit name │
│ 3. Ask if numbers should be params  │
│ 4. Add to shortcuts.json            │
│ 5. Mark suggested=1 in query_stats  │
└─────────────────────────────────────┘
```

**Key Benefit:** Because we key by COMMAND, the following all count as the same:
- "find large files" → `find . -size +100M`
- "find larg files" (typo) → `find . -size +100M`  
- "show large files" → `find . -size +100M`

Use count = 3 (not split into 3 different entries)

### Flow 4: Automatic Cleanup

```
CLI starts
    │
    ▼
┌─────────────────────────────────────┐
│ Check metadata.last_cleanup         │
│ If > 24 hours ago → run cleanup     │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│ DELETE FROM history                 │
│ WHERE created_at < (now - 30 days)  │
│                                     │
│ DELETE oldest entries               │
│ IF count > 2000                     │
│                                     │
│ Update metadata.last_cleanup        │
└─────────────────────────────────────┘
    │
    ▼
Ready to accept commands
```

## Configuration Options

Settings can be configured in `~/.shell-agent/config.json`:

```json
{
  "settings": {
    "historyEnabled": true,
    "historyRetentionDays": 30,
    "historyMaxEntries": 2000
  }
}
```

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| historyEnabled | boolean | true | Enable/disable history tracking |
| historyRetentionDays | number | 30 | Days to keep history entries |
| historyMaxEntries | number | 2000 | Maximum history entries to keep |

## Privacy & Security

### Local-Only Storage
- All data stored locally in `~/.shell-agent/history.db`
- Nothing leaves the machine except AI API calls
- No cloud sync, no telemetry

### File Permissions
- Database file: `0o600` (owner read/write only)
- Same security model as config and shortcuts

### Sensitive Commands
- Users can disable history via config
- Clear history anytime with `s --clear-history --all`
- Retention policy auto-deletes old entries
